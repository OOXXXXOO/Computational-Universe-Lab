## 0. 裁定

v7 已使 B3–B6 的 Parent-v3 prestructure、transition 与 certificate 路线可实现；但 v6
的 B7–B10 仍有四类结构性矛盾，不能靠实现技巧绕过：

1. B7 把 legacy response wire 就地改成 V3 body，并要求 C19 提供不存在的
   `ControlRegistryEntry` 与 qualification；它还只消费 certificate wrapper，丢失完整
   certification outcome lineage。
2. B8 的单分支 block issuer 可以泄漏半对 capability；geometry 的 `status + reason_ids`
   不能区分“已评估为 false”和“不可评估”，七项 observation 也没有逐项 presence/formula
   合同。
3. B9 用 C19-only closed evidence 表示 C01–C18 的 21 个 inherited success，并复用硬绑
   Parent-v2 的 materialization/response/typed-termination wire；31 项 scenario、44 个 block、
   三坐标与九项表示不变量因而不能组成一条可复放证据链。
4. B10 声明了 out-of-band trust anchor，却没有确定性 loader；reviewer 无法在签名前取得
   issuer 最终验证的 exact statement bytes；四个 artifact ref 也没有与四份 exact body
   建立机械的一一连接。

本勘误只修复这些结构矛盾。v6 B1–B6 经 v7 合并后的合同保持不变，唯一例外是 B6 增加一条
不改变 raw wire 的 private outcome→certificate lineage seam，供 B7/B8 保存完整 outcome。
`c19_freeze`、`grid_freeze`、四叶 artifact contract、state ceiling、全部阈值和科学语义均不改。
本文仍是 `DESIGN_ONLY_NO_AUTHORITY`，不签发任何 capability、状态或 GPU checkpoint。

## 1. B7：并行 V3 response wire

`rulespace_v3.response` 继续拥有 legacy v1 raw records，并只抽出 authority-neutral 数值 core。
`rulespace_v3.application_response_v3` 拥有全新的 V3 run/reference/shell/paired records；不得把
legacy 同名 wire 原地“升级”。公开 issuer 只接 Parent、B2 materialization 和两份完整
`VerifiedDynamicsCertificationOutcomeV3`，run spec、grid、basis、阈值、reference 与 shell
全部由 live lineage 内部派生。

V3 wire 不含 `ControlRegistryEntry` 或 `qualification_sha`。执行前缀固定为 reference → shell
→ actual → matched-ablated；reference failure 后没有 shell/branch attempt，shell failure 后没有
branch attempt，branch 总是 actual 先于 matched。只有完整双分支成功才签 paired capability。

B6 的 private outcome view 保存 raw outcome、success certificate 与六个 exact live upstream；
certificate view 反向保存 originating outcome identity。`require_dynamics_certificate_v3(outcome)`
只能从 recursively reverified success outcome 返回既有 live certificate，不能从 raw certificate
重铸。这条 seam 不改 `DynamicsCertificationOutcomeV3` 或 `DynamicsCertificateV3` wire。

## 2. B8：atomic block pair 与七项 geometry evaluator

单分支 `issue_verified_response_block_from_closed_evidence` 被移除。新 issuer 先依次构造 actual、
matched-ablated 两份 raw `ResponseBlock`，两份均完整验证后，才在同一个临界区签两份既有
`VerifiedResponseBlock` 与 pair outcome；任一失败均保留两槽 attempt prefix，并签零个 block
capability。geometry 只消费 closed evidence 与完整 `VerifiedResponseBlockPairOutcomeV3`，不接收
两份可由 caller 拼接的 block。

这个 atomic mint owner 同时支持两个不可混用的 authority route：current C19 的 closed
evidence，以及 inherited Parent-v3 的完整 response outcome。后者由不 import `blocks`
的 lower `inherited_control_execution_v3` 签发；`blocks` 可因而递归复核它并使用同一
双分支 raw-build/verify/mint 临界区。三坐标与预言比较上移到
`inherited_control_measurement_v3`，因而不会形成 `blocks ↔ inherited` 循环 import。

七项 prerequisite 的 `status` 只表达 evaluability；`predicate_passed` 只在 evaluable 时为 bool。
第二项在 C19 上冻结为白化 coisometry 路线，不再把自然语言中的“or”留给实现选择。每项的
observation presence、公式、阈值来源与顺序均由 registry 固定，caller 不能提交 observation、
metric、whitener、incidence、projector 或阈值。
七项全部可评估但任一谓词为 false 时，geometry outcome 仍是 defined，完整
evaluation 仍被保留；这是科学控制结果为假，不是计算 undefined。

## 3. B9：31 项 typed union 与三坐标总装

`ParentV3ScenarioReplayAuthorityV1` 下移到独立 lower owner；它从 Parent-v3 的 P blob 按 ordinal
复放完整 application/scenario/source closure。21 个 inherited success 先在不 import `blocks` 的
lower owner 中产生完整 typed materialization/response prefix，再由 `blocks` 原子签发双 block，
最后由 measurement owner 计算三坐标并比较预言；C19 使用 B7/B8 current route 与
`c19_refreeze_v2` 的 v2 application/scenario identity，不得沿用旧 controls JSON 的 C19 v1 ID。二者汇合到
`V3M0BlockSuccessOutcomeV3` 的 exact route-XOR，而不是让 inherited case 冒充 C19 closed evidence。

总装固定 31 项：22 个 block-success 槽（21 inherited + C19）、7 个 expected typed
termination、2 个 C20 analysis。每个 block-success 槽都保留 typed outcome 与 actual/matched-ablated
可空 SHA 对；SHA 对的 presence 只由该槽原子 block pair 是否成功决定，不由后续科学
谓词真假决定。只有 22 个 pair 全部构件完整时才能按 scenario order 展平为固定 44 个 SHA。
另有 1 份 B1 window calibration 与 9 份全名表示不变量。所有
UndefinedReason wire 使用小写 enum value。

每个 inherited success 保存 raw `CausalResult`、`GeometrySpectrum`、`SigmaResult` 的适用三坐标
observation，并机械比较 Parent prophecy。C04 survival 与 C15–C17 geometry/coverage 阈值由新
Parent-v3 calibration records 保存，不复用 legacy Parent/permit capability。表示不变量总是保存
`K_surv` spectrum/trace/count，适用时保存完整 `s/g/c` 谱与主坐标；`passed` 为 nullable bool，
不可由一个自声明的 canonical JSON object 代替。
同样，inherited prediction 可评估但不匹配时，`prediction_passed=false`、route status 仍为
defined，原子 block pair 与三坐标证据不得被丢弃。只有坐标或上游构件不可定义才进入
`first_undefined`。

最终 resolver 只委托已有 `rulespace_v3.state.resolve_v3m0_state`。22 个 required block report
不混入七个 typed termination；`no_unexpected_downstream_capability` 由七个 false wire 与 issuer
registry 的零 mint 共同证明。

## 4. B10：具体 trust provider、可预取签名 bytes 与四叶连接

production loader 是零参数 API，唯一读取
`/etc/computational-universe-lab/trust/v3m0-campaign-checkpoint-anchor-v1.json`。它使用
`O_RDONLY|O_CLOEXEC|O_NOFOLLOW`，并对 regular/root-owned/single-link/not-group-or-other-writable/
1..65536 bytes 做 `fstat`；随后 strict UTF-8、duplicate-key/nonfinite-reject JSON 解析。没有
path/env/raw/serialized fallback。测试替身只可经 private graph/provider factory 注入。

reviewer 先调用 prepare API 取得 exact `UnsignedPortableEnvelopeStatementV1` 与 canonical bytes；
final issuer 从同一 live chain 重算并要求 statement 与 bytes exact equality，再验证两个不同 role、
不同 key 对同一 bytes 的签名。四叶固定连接 Parent body、controls result、response result、state
decision；ref 的 path/kind/schema/order 与 v6 artifact contracts 逐项相等，artifact root 覆盖这四份
exact bytes。HALT 是合法可签状态；detached verifier 幂等，重复消费只属于下一 stage issuer。

generic campaign owner 不 import Parent crypto；Ed25519/canonical statement codec 位于独立 lower
leaf，并用 Parent fixture 做 golden parity。anchor 必须在解析任一 attacker-controlled bytes 前完成
live reverify。

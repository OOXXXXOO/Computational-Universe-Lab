## 1. Overlay 算法

机器测试必须按以下顺序建立 effective registry：

```text
VERIFY v6 raw SHA and ordered registry SHA
VERIFY v7 raw SHA and ordered registry SHA
APPLY v7 effective merge
VERIFY v8 raw SHA and ordered registry SHA
APPLY v8 effective merge
VERIFY v9 raw SHA
VERIFY every v9.1 expected_prior_value_sha256 against the effective value
APPLY v9.1 operations in listed order
REJECT every unlisted prior mutation
```

ordered-JSON digest 沿用 v8 算法：保留 mapping insertion order，将 dict 递归冻结为
`tuple[(key,value),...]`，再以
`json.dumps(ensure_ascii=False,separators=(",",":"))` 编码并做 SHA-256。它不是 project
canonical JSON；record/runtime self-SHA 仍使用 project `canonical_sha`。

v6/v7/v8 的 path、schema、raw SHA 与 ordered-registry SHA 全部作为 machine registry 的
`base_contracts` exact fields 冻结；任何一项缺失、错序或不相等都在 overlay 前 fail closed。

四项 operation 的顺序固定为：

```text
/record_catalog/CurrentScenarioResponseContractV3
/record_catalog/ResponseRunSpecV3
/record_catalog/CurrentCurvatureNormalizerProtocolV1
/record_catalog/CurrentReadoutCalibrationSpecV3
```

前两项 replacement 的 prior digest 分别是：

```text
CurrentScenarioResponseContractV3
  114dc1dad1a0fb24a253177d5daa83ff18acb38765b3bd76da8ed1d6f8d2c1ff
ResponseRunSpecV3
  4f432bcc4d3bee7089a7795966cb9af26cca0ef1787720375e734028ae43ec06
```

两个 addition 在 materialized v8 effective catalog 中必须 absent。replacement 后旧 field-set
body 即使递归重签也必须失败；不得保留旧 schema adapter。

## 5. Reviewer receipts 与 production handoff

两份 receipt 的固定角色分别为 `CORPUS_REPLAY` 与 `METRIC_REPLAY`，reviewer ID 必须不同。
receipt 不声称 cryptographic human signature，只证明两个 fresh-process replay 的 exact protocol、
source、argv、环境、输入 root、独立 replay-report stdout root、输出 root 与 verdict。stdout report
不含 receipt，故没有 stdout/receipt 自引用。receipt 是 total process outcome：严格 report 解码失败
时五项 replay 输出必须全为 null，并按冻结 reason 顺序产生 `REJECT`；解码成功时五项必须全部
来自该 report，只有 exit、环境、源码、输入、decision、survivor 与 winner 全部一致才能 `ACCEPT`。
Python/environment/Git/export/source/input/cwd 启动前校验失败、spawn `OSError`、1800 秒 timeout、
signal 与普通非零 exit 分别有 exact termination kind、nullable exit/signal presence、stdout/stderr
byte hash 与 reason 映射；即使子进程因 precheck 未启动、spawn 失败或被杀死，外层 runner 也必须
确定地产生 receipt，而不能让 review-halt 停在“未完成”。
runner 不得调用无界 `communicate()`/drain：stdout/stderr 各有 1 MiB hard cap，以 64 KiB
nonblocking selector chunks 和 absolute monotonic deadline 读取；overflow、TERM/KILL grace、最终
pipe close 与 export cleanup 都有独立 typed reason 和有限截止时间。route 与两类 reviewer-child
reachable closure 另经静态扫描，禁止 subprocess/popen/posix/pty/fork/exec/spawn/process-pool/
setsid/ctypes/network/dynamic import，
并禁止 `os`/`posix`/`signal` 的 kill/killpg/setsid/pthread-kill/raise-signal surfaces；只允许最终
一次 canonical replay-report stdout write。因此候选代码不能杀死外层 runner，也不能靠后代进程
继承 pipe 或脱离 process group 逃逸。
该禁令不再只匹配公开函数名：`os`/`posix`/`pty`/`subprocess`/`multiprocessing`/
`concurrent`/`ctypes`/`_posixsubprocess`/`importlib`/`runpy`/`socket` 按 module root 整根拒绝，
外部私有 attribute 与 module/callable 间接流也拒绝。lab-authored common/compare 的外部调用
必须来自 exact pure-call allowlist，route 从 common 只能显式导入冻结异常类，不能借
common module globals 转发任何调用。
同样，lab initializer/common/compare 的 `Import`/`ImportFrom` 也有逐模块精确白名单：initializer
必须是空 blob，child bootstrap 只能导入冻结的纯 stdlib/numeric 模块、origin-bound
`rulespace_v3` 模块与三条 route；外层 runner 所需的 process/tar/temp 模块只能在明确
的 parent-only 函数内局部导入，且不可达于两个 child root。所有未列导入都拒绝，
包括仅靠 import-time side effect 启动外部进程的 `antigravity`/`webbrowser` 类反例。
两份 ACCEPT receipt 必须钉住同一 evidence commit
`E`、D0/D1 raw/self/decision roots、common corpus、mutation、metric、environment 与 source roots；
wall time/memory 只在 full artifact provenance 中保留，不进入 replay decision projection。

reviewer 不能从当前 worktree import：外层 verifier 使用受信 `/usr/bin/git` 从 `E` 将 exact
common/route 源码、`rulespace_v3`、machine registry、corpus fixture 与 D0/D1 输入 blobs 导出到
全新临时目录。Git mode 先由 `ls-tree` 验证；tar mode 不作 Git mode 使用，只验证 entry type/path，
提取后再按原 executable bit 统一 chmod 为只读。随后以 D1 environment manifest 钉住的 Python
realpath/raw SHA 启动 `python -s -m ...`。环境先清空再写入冻结的 hash seed、UTF-8、禁 user-site、
禁 bytecode 与单线程 BLAS literals；cwd/import root 都只能是该 immutable export。输入 bytes 在
strict parse 前还必须逐一等于 `E:path` 的 blob bytes。

`E` 本身也不是代码信任根。在启动子进程前，外层 verifier 必须把 `rulespace_v3`
完整子树、machine registry、corpus、lab initializer/common/compare
逐 path/mode/type/blob OID 绑定到 D0 声明的 `common_commit_sha`，三个 route 则各自绑定到
它的 `route_commit_sha`；lab package 不得有第七个 leaf。两个 reviewer role 还要按 Python 实际
import 语义扩展可执行闭包，包含每一级 package `__init__.py` 和所有 repository-local
module；任一未列入、无源提交、或在 `E` 中漂移的可执行 blob 都必须在 spawn 前以
`REPLAY_EXECUTABLE_SOURCE_ORIGIN_MISMATCH` typed REJECT。receipt 单独保存该完整源码闭包根，
不再以单个 compare.py SHA 代替依赖闭包。
现有仓库根 `experiments/__init__.py` 会主动导入与 B7 无关的 R10 模块，因此它明确不进入
export；新根中 `experiments` 只能是单 portion PEP 420 namespace package，不得受当前
worktree 或第二 namespace portion 影子覆盖。

源码与环境前检是 total observation，不是“失败就无法验证 receipt”的硬断言：receipt
同时保存 expected/observed source-closure root 与 pass bit，以及 expected/observed environment root
与 pass bit。失败态仍能通过 receipt 结构验证，但必须是 `PRECHECK_FAILED` 和精确
REJECT reason；只有两个 pass bit 都为 true 才可 ACCEPT。外层已从 Git objects 重算的
expected source-closure root 通过唯一的冻结 argv 参数传入 child，child 用它构造
`replay_input_root_sha`；外层再把 report 与自己的 expected root 逐字节比对。
严格解码 report 后，receipt 还必须保存并比对 report 自称的 reviewer role、protocol、
`E` 与 input root；前三者不同产生 `REPLAY_REPORT_IDENTITY_MISMATCH`，input root 不同仍用
`REPLAY_INPUT_ROOT_MISMATCH`。因此 corpus/metric 两个 role 不能用同一份冒名 report 坍缩。

为使上述 child 禁令不与旧 production import-time 机制自相矛盾，P0 新增唯一纯模块
`rulespace_v3/b7_replay_core_v1.py`。它只包含 canonical raw validators 子集与五个
authority-free leaf，只导入冻结的 pure stdlib/NumPy/SciPy 数值模块，不导入任何现有 authority、Parent、
response、runtime 或 Git 模块。`rulespace_v3/__init__.py` 同时改为保持原公开名称的惰性
导出，因此 child 实际执行的 rulespace 闭包精确只有 package initializer 和 pure core。
initializer 的 module AST 也是 exact：只能是 docstring、原九个 `__all__` literal 与唯一
`__getattr__(name)`；该函数必须零 decorator/default/annotation，body 只能按九个名称逐项

comprehension/named-expression，因此 decorator/default 隐藏 `exec` 的反例在 Python 执行前即拒绝。

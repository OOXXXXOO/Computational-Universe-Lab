# V3-M0 fp64 Runtime 语义探针设计

> 日期：2026-07-31  
> 状态：设计冻结  
> 适用范围：`build_fp64_enclosure_protocol` 与
> `verify_fp64_enclosure_protocol`

## 1. 目的

现有 `Fp64EnclosureProtocol` 冻结了 binary64、round-to-nearest、
gradual-underflow、no-FTZ/no-DAZ、`nextafter` 和 signed-zero 语义，但此前只验证 wire
声明，没有机械确认当前进程/线程实际执行这些语义。

本设计在不改变 public wire、schema、阈值或证书字段的前提下，为每次 protocol build 和
verify 增加实时算术探针。探针失败或抛异常时统一 fail-closed。

## 2. 选择的方案

采用 portable effective-behavior probe，不读取 x86 MXCSR、ARM FPCR 或 libc 私有状态。
所有输入由运行时 integer bits 经 `struct.pack/unpack` 构造，再实际执行运算，最后只按
binary64 exact bits 比较结果。

没有采用：

- 平台寄存器读取：架构、ABI 和线程模型不统一；
- 只读 `sys.float_info`：无法检测当前 rounding mode、FTZ 或 DAZ；
- 缓存首次结果：floating environment 可能是线程局部状态，每次 public build/verify 必须
  重测。

## 3. Runtime observation

新增 private frozen `_Fp64RuntimeObservation`。它只活在内存中，不进入
`Fp64EnclosureProtocol` payload。字段保存：

- `struct.calcsize("d")`、`sys.float_info.radix/mant_dig/min_exp/max_exp`；
- even-lower tie 与 odd-lower tie 的结果 bits；
- `minnormal * 0.5` 的结果 bits；
- `minsub * 2^(mant_dig-1)` 的结果 bits；
- `minsub + minsub` 的结果 bits；
- `nextafter(+0,+1)`、`nextafter(-0,-1)`、`nextafter(±minsub,+0)`、
  `nextafter(1,±∞)` 的结果 bits；
- runtime 构造的 `+0/-0`、`copysign(+0,-1)`、`-0 + -0`、`-0 * +1`
  的结果 bits。

输入 `1.0`、相邻 normal、half-ulp、minnormal、minsub 和 signed zero 全由 integer bits
解包。DAZ 放大因子从 runtime `sys.float_info.mant_dig` 计算，禁止写可被常量折叠的
完整浮点表达式。

## 4. 机械判据

validator 只接受 exact `_Fp64RuntimeObservation`，逐字段与冻结 integer/bits 比较：

1. double width 8 bytes、radix 2、precision 53、min/max exponent 符合 binary64；
2. `1.0 + half_ulp` 回到 even `1.0`；
3. odd next-up `1.0 + half_ulp` 进到下一个 even value；
4. `minnormal * 0.5` 得到 bit `0x0008000000000000`，证明输出不 FTZ；
5. `minsub * 2^52` 得到 minnormal，证明输入不 DAZ且不与 FTZ 混淆；
6. `minsub + minsub` 得到 bit 2；
7. `nextafter` 的每个邻接和 signed-zero 结果逐 bit 正确；
8. signed-zero 的构造、`copysign`、加法和乘法逐 bit 正确。

rounding mode 反例被两条 tie 联合覆盖：

- upward 会使 even-lower tie 进到 odd next-up；
- downward 或 toward-zero 会使 positive odd-lower tie 留在 odd lower；
- 因而任何这三种非 RN 模式至少失败一条。

## 5. Public 接线

新增 private `_require_fp64_runtime_environment()`：

```text
observe runtime → exact-bit validate → verified private observation
```

observer、bit conversion、算术或 validator 任一异常都统一转成
`RuntimeError("fp64 runtime semantics are not certified")` 并保留 cause。

现有 protocol body 构造下沉为 private no-probe builder：

- public `build_fp64_enclosure_protocol()` 先 probe，再构造；
- public `verify_fp64_enclosure_protocol()` 先 probe，再验证 caller body，并用 private
  builder 重建 expected；
- public 函数签名和 wire 完全不变；
- verify 不通过调用 public build 重复探针。

## 6. 测试合同

先写 RED，覆盖：

1. 当前环境 observation 全字段 exact-bit GREEN；
2. 对 observation 每个字段逐一替换错误值，validator 全部拒绝；
3. 模拟 upward 的 even-tie bits 拒绝；
4. 模拟 downward/toward-zero 的 odd-tie bits 拒绝；
5. 模拟 FTZ、DAZ、错误 nextafter 和 signed zero 各自拒绝；
6. observer、bit pack/unpack、nextafter 或 validator 抛异常时 public build/verify
   fail-closed；
7. source inspection 确认输入由 runtime bit unpack 构造；
8. public build/verify 签名及 protocol payload 字段不变；
9. 现有 fp64、exact-zero 与 C04 full64 回归全绿。

本任务保持谱 residual subtraction 的 `MINIMUM_NORMAL` 保守 additive，不恢复
`MINIMUM_SUBNORMAL`。

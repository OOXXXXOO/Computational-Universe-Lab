## 4. 正频 source/readout 合同

本节只允许一套 basis wire，不保留 common-basis 或 scenario-basis 的
第二方案。在复化的 20 维 state space 中，对 `a=0,…,9` 定义

```text
B₊[:,a] = (e_qₐ - i e_pₐ)/√2       # shape 20×10
P = B₊†                                   # shape 10×20
```

必须重算并冻结：

```text
B₊† B₊       = I₁₀
P P†         = I₁₀
J₂₀ B₊       = i B₊
P J₂₀ B₊     = i I₁₀
rank(B₊)     = 10
rank(P)      = 10
rank(P J₂₀ B₊) = 10
```

`B₊` 是 tall isometry，不是 20 维空间上的 coisometry；`P=B₊†` 才是可执行
readout coisometry。common `BasisManifest` 在 source/readout 两个 role 上的 raw vectors
均为精确 `I₂₀`：

```text
B_common_source = I₂₀       # raw source rows, shape 20×20
W_common_readout = I₂₀      # raw readout rows, shape 20×20
C_source = B₊                    # selector, shape 20×10
C_readout = P                       # selector, shape 10×20

source_injection
  = B_common_source.T @ C_source
  = I₂₀.T @ B₊
  = B₊                           # shape 20×10

readout_coisometry
  = C_readout @ conj(W_common_readout)
  = P @ conj(I₂₀)
  = P                              # shape 10×20
```

由于 source `BasisManifest` 以 raw row vectors 保存、readout 执行器对 raw
rows 取共轭，scenario 的两份 raw basis vectors 必须逐位相同：

```text
scenario_source_raw_vectors  = source_injection.T
                             = B₊.T
scenario_readout_raw_vectors = conj(readout_coisometry)
                             = conj(P)
                             = B₊.T                    # both shape 10×20

scenario_source_raw_vectors.T   = B₊
conj(scenario_readout_raw_vectors) = P
```

因此 raw common basis、selector、derived scenario basis 与 executable maps 必须全部作为
独立 exact tensor body 递归绑定，并机械重算上述两条等式。若把 `P` 本身当作
scenario raw readout rows，运行时会再取共轭，正频 source 与错向 readout
的 effective rank 会降为零。

source trials 唯一为正频 source 坐标上的 `I₁₀`。Parent 的预注册 actual/matched
shell/response rank 均为 `10/10`；这些是实验前的 expected ranks，必须在后续有限阶
endpoint 与 paired response 中实测重现，不得由上述解析矩阵直接签 PASS。
旧四通道 public basis 无法承载上述 shape，也无法存在秩 10 的 source
isometry/readout coisometry；不得以 selector splice、padding 或另一份探针 basis 绕过。

## 9. 必须实现的机械签发闭合

当前 `parent_freeze_v2/parent_authority` 尚未实现本节的双 receipt、clean-HEAD、
single-parent、strict path/hunk diff 和内部 signing-audit capability。下述流程全部是
**MUST IMPLEMENT**，不是当前 issuer 已有的能力，也不可以仓库外的口头复审代替。

### 9.1 signed source 必须继承并存

新 `ParentFreezeV3Manifest` exact schema 必须删除单数
`signed_incremental_erratum: SignedSourceRefV1`，改为递归哈希的 canonical ordered
`signed_source_refs: tuple[SignedSourceRefV2, ...]`。relative path 按 UTF-8 bytes 升序、
不得重复，且至少必须同时包含：

1. `docsv3/v3-勘误-geometry-scenario-audit-2026-07-31.md`：C05–C18 历史增量依据；
2. `docsv3/v3-设计勘误-C19-refreeze-v2-2026-08-01.md`：C19 refreeze v2 依据。

每份 exact ref 必须绑定 role/scope、relative path、SIGNED raw SHA、preparation
commit `P` 与自身 canonical SHA。签发时两份文档都必须是 `SIGNED`，并与
observed raw bytes 逐位一致；任一缺失、仍为 DRAFT、顺序漂移或 SHA 不符都
阻断发行。C19 ref 不得覆盖、替换或使 C05–C18 ref 不可达；旧单数字段
在新 schema 中必须被当作 unknown field 拒绝。

### 9.2 `P` → 双 receipt → clean `S=HEAD` → 内部 audit → `issue_v3m0_parent_freeze_v3()`

1. **clean preparation commit `P`**：`P` 在 clean tree 中一次性收口 v3 wire、C19
   code/tests、Parent candidate、两份 signed-source DRAFT、source closure、root-bearing
   builder/issuer/signing-audit 逻辑与定向攻击。`P` 明确 non-authoritative；root-bearing
   files 的逻辑实现必须在 `P` 中完整复审，不得留到 `S` 修改；
2. **`P` 后双 review receipt**：数学/合同与 authority/边界 reviewer 必须
   独立生成两份 exact PASS receipt。每份 receipt 必须绑定同一 `P` SHA、
   reviewed candidate root、角色、复审 path/SHA closure、verdict 与 receipt SHA；角色
   不得重复。任一复审促成 body 改动时，必须重做新 `P` 和两份 receipt；
3. **allowlisted signing commit `S`**：`S` 必须是当前 clean `HEAD`，只有一个
   parent，且 `HEAD^` 必须逐位等于 `P`。`S` 只允许修改 `P` 预冻结的
   constant-literal/document-status/receipt allowlist：最终 P/candidate/doc/receipt SHA
   literals、两份文档的 `DRAFT→SIGNED` 状态与 exact receipt records。任何构造、
   schema、数学、grid、threshold、executor、test logic 或 root-bearing control-flow
   hunk 都越界；
4. **issuer-internal signing audit**：`issue_v3m0_parent_freeze_v3()` 的第一步必须是内部重放，
   而非依赖外部声明“已复审”。它必须拒绝 dirty tree，验证 `HEAD=S`、
   `S` 唯一 parent 为 `P`，重放两份 exact receipt，对 `P..HEAD` 做逐 path/
   逐 hunk allowlist 审计，并重算两份 SIGNED doc/raw SHA、canonical signed-source
   tuple、candidate root、reviewed path closure 与 source closure。root-bearing files 必须与
   `P` 的 reviewed logic 一致，只容许上述 literal hunks；
5. **不可伪造的内部 audit capability**：第 4 步通过后，issuer 内部才能以
   模块私有 token/live registry 生成不对外暴露的 signing-audit capability，及其
   hashed record。record 必须绑定 observed `P`/`S` SHAs、两份 receipt SHAs、
   `P..HEAD` diff digest/allowlist ID、signed-source tuple root、candidate root、source-closure
   root 与 audit SHA。不得有 caller-supplied audit、raw hydration、subclass 或公开 promotion；
6. **零参 Parent 发行**：只有内部 audit capability 通过当次 live 重验后，
   `issue_v3m0_parent_freeze_v3()` 才可构造 exact `ParentFreezeV3Manifest`，把 observed signing commit
   `S=HEAD` SHA、audit record、canonical signed-source tuple 和 current authorities 全部绑入
   Parent body，再机械计算 current Parent root 并返回 exact live opaque
   `VerifiedParentFreezeV3`。

这些检查必须在 issuer 每次入口内重放。`S` 之后的任何提交会使
`HEAD^ != P`，任何 dirty change 会使 clean-tree 门失败，任何 root-bearing 逻辑
改动会使 `P..HEAD` hunk 门失败。`reviewed candidate root` 是非权威输入；
current Parent root 则另外绑定 observed `S`、audit、signed sources 和 current
authorities，两者不得互换。**current Parent root 不回写 `S`**；`S` 不包含
未来 Parent root literal，因而不形成 commit/doc/root 循环。

现在不存在符合上述程序的 `P`、双 receipt、`S` 或 internal signing-audit
capability；本文也不预填任何未来 commit/SHA。

## 1. 发现的三个合同缺口

### 1.1 D0 corpus 没有 synthetic graph

v9.1 `B7LabCorpusFixtureV1` 只嵌入 corpus spec、mutation universe、metric spec、
environment 和七份 D0 transcript。但 transcript 中的
`response_run_spec_fixture` 和已完成 response 必须调用需要完整 graph 的 pure
validator。因此“七份 transcript 全部 strict validate”在 v9.1 corpus 输入上不可实现；
跳过 graph-dependent validator 会 fail open，临时构造 graph 则会让 D0 和 D1 脱离同一
状态空间。

### 1.2 Python invocation path 不等于 resolved target realpath

当前受控环境实测：以 repository venv invocation path 执行
`python -s` 可导入 NumPy/SciPy；将同一 symlink chain 的最终
resolved target realpath 直接作为 `argv[0]` 时，立即出现
`ModuleNotFoundError: numpy`。Python 通过 invocation path 附近的 `pyvenv.cfg`
恢复 venv 语义；仅冻结 realpath/raw SHA 不能同时冻结“执行哪个环境”。

### 1.3 macOS 当前无 descriptor-bound Python exec 路径

当前开发 host 观测到 `os.fexecve` 与 `os.execveat` 不可用，将已打开的
Python fd 经 `/dev/fd/<n>` 执行返回 `EACCES`。因此现有 `Popen(path, ...)`
只能在完整 precheck 后立即重查 path identity，不能诚实地声称 kernel 必然
执行了先前 descriptor 所哈希的同一 bytes。

## 2. 勘误裁定

### 2.1 Graph-bearing corpus V2

新增 `B7LabCorpusFixtureV2`，字段顺序唯一固定为：

```text
fixture_schema_version
corpus_spec
mutation_universe
metric_spec
environment_manifest
synthetic_graph_manifest
ordered_d0_transcripts
fixture_sha
```

`synthetic_graph_manifest` 是完整 `B7LabSyntheticGraphManifestV1` body，不是单个 SHA。
`fixture_sha` 删除且仅删除自身后重算，因而 graph 的 complete body 进入 corpus
self root；fixture 文件的 raw SHA 仍由 root test 在 parse 前验证。

`validate_corpus_fixture_v2` 的顺序为：strict top-level，重算 corpus/mutation/metric/
environment，然后对唯一 graph 调用一次
`validate_synthetic_graph_manifest_v1`，再将这一个已验证 body 传入七份
transcript 的所有 graph-dependent run-spec/response validator。禁止跳过、替换、
重签或逐 transcript 构造 graph。

DAG 必须显式满足：

```text
v9.2 raw-root verification
  → synthetic graph validate/freeze
  → corpus V2 raw/self freeze
  → D0
  → D1 when D0 has survivors
```

environment V2 也必须在 corpus freeze 前完成。D1 嵌入 graph 的 project canonical
bytes 必须与 fixture graph 逐字节相等；仅 `graph_sha` 相等不足够。

### 2.2 EnvironmentManifest V2

新增 `B7LabEnvironmentManifestV2`，将 Python 身份分为不可互换的两个 owner：

- `python_invocation_path`：absolute normalized path，可以是 symlink，是 reviewer/probe
  的唯一 `argv[0]`；
- `python_executable_realpath` + `python_executable_raw_sha256`：最终 regular executable
  target 及其 raw bytes 身份，不允许替代 invocation path 启动子进程。

另冻结 `python_invocation_identity_sha`、`python_venv_prefix`、
`python_pyvenv_cfg_path` 和 `python_pyvenv_cfg_raw_sha256`。identity 投影包括：

1. invocation 到 target 的 ordered `lstat`/`readlink` chain，最多 40 hops，重复 inode
   或超限即拒绝；
2. target realpath 与通过同一 `O_NOFOLLOW` fd 读取的 raw SHA；
3. 从 invocation path 目录逐级向上找到的唯一 nearest `pyvenv.cfg`、其 raw SHA
   与 parent venv prefix。

完整 precheck 还必须以 invocation path、`-s`、清空后的冻结环境启动有界
import probe。probe 必须成功 import `numpy`/`scipy`/`threadpoolctl`，只输出一份
canonical JSON report + LF，并与 manifest 的 Python/NumPy/SciPy 版本、platform、
dtype、byteorder、threadpool、`sys.executable` realpath 和 `sys.prefix` 逐项相等。

`environment_sha` 包含 invocation path、resolved target、target raw SHA、invocation identity、
venv/config 与 probe 归属字段。D0、D1 与两名 reviewer 必须使用同一份 exact body。

### 2.3 复放威胁模型的诚实边界

reviewer 启动前必须完成：

1. invocation symlink chain、resolved target、same-fd target raw SHA、nearest `pyvenv.cfg`、
   venv prefix、import probe 与 Environment V2 self root 的完整 precheck；
2. 在 `Popen` 紧邻的程序点按同一 identity tuple 立即重查；
3. 重查返回 true 后，下一个有副作用的操作就是以 invocation path 为
   `argv[0]` 的 `Popen`。

这一声明依赖受控 host 先验：在 final recheck 到 kernel exec 的短窗口中，
没有并发进程改写 invocation symlink chain、resolved target 或 `pyvenv.cfg`。
它不是 descriptor-bound 执行证明，也不允许声称在 adversarial path replacement
下仍严格执行预检时的 same bytes。

若未来需要更强的 adversarial same-byte 主张，必须另行冻结并审核一个能保留
venv invocation 语义的 descriptor-bound launcher，或等价的 immutable deployment
profile。这是更强安全声明的平台部署先验，不是当前 B7 物理实验门，
不得把它偷换为修改阈值或撤销 reviewer 的理由。

## 3. Reviewer immutable materialization

reviewer 的 immutable export 必须同时包含 v9.1 base registry 和 v9.2 overlay，并从
Git object `E` 验证两份 bytes。required inputs 由单个 `registry` 拆为
`registry_base`/`registry_overlay`；child 必须先物化 exact v9.2 effective lab
contract 再复放 D0/D1。只导出或只验证其中一份 registry 必须在 spawn 前
typed REJECT。

reviewer command template 的首个 placeholder 替换为
`{FROZEN_PYTHON_INVOCATION_PATH}`。resolved target realpath/raw SHA 和 invocation identity
只是 precheck/recheck 来源，绝不作为 `argv[0]`。两个 role 仍是独立 fresh
process，stdout/stderr cap、timeout、process group、cleanup 和 total receipt 语义不放宽。

v9.1 已冻结 route reachable closure 中的 `__import__`/`getattr` 等七个调用
禁令，以及 reviewer child 中十二个 forbidden exact names；v9.2 逐字复用，
不允许实现扩展或放宽。为避免 source-closure membership 实现先于合同，
overlay 另将每个 membership 的 11 个字段、wire type、role/route group order、
组内连续 ordinal、去重规则和 expected/observed root 算法机械冻结。算法不变；
唯一 v9.2 delta 是 overlay JSON blob 进入 common-origin exact blob set，不进入
executed-module membership sequence。

## 4. Pure-core projection 不重冻结

v9.2 修改的是 common-layer corpus/environment/reviewer joins；八个 pure production-body
validator 的语义和 literal 没有改变。因此 `rulespace_v3.b7_replay_core_v1`
继续验证 v9.1 projection SHA-256：

`bafbaeb75e890715464c1fff6e6e0cbf1d4f56bb53a3817a9b2d12d2a3c27ff9`

v9.2 overlay 本身由独立 raw SHA root test 约束，不进入上述 pure projection，
也不迫使重写 core 的大 literal。这不是跳过 overlay：common/D0/D1/reviewer
必须同时验证 v9.1 raw root 和 v9.2 raw root。

## 5. 生效与审计结论

v9.2 在首份 B7 corpus fixture 或 D0 artifact 产生前生效。新执行不得使用
`B7LabCorpusFixtureV1`，不得提供 v1→v2 migration adapter；v9.1 文件保持
immutable historical base。

当前类型状态是 `PRE-D0-CONTRACT-BLOCKED-NOT-A-SCIENTIFIC-FAIL`，直到 common/
compare、graph-bearing fixture、Environment V2 probe/recheck 和 reviewer export 实现均通过
v9.1 + v9.2 root tests。本勘误不产生 M3′/V3-M0 PASS/FAIL，不创建 runtime
capability，不生成 GPU permit。

**签发结论：** 以 v9.2 overlay 取代 v9.1 中对 B7 lab corpus、environment 和
reviewer materialization 的相冲突条款；其余 v9.1 条款继续生效。未完成本文的
实现与预飞前，D0 不得启动。
